Execution boundary

Native protobuf queries and legacy measure QL use the existing vectorized native operators. DistributedPlan.ExecuteBatches exposes their output before the final protobuf iterator. QL consumes that output through ql.NativeScan; native callers use the same result’s final iterator. Standalone execution exposes the equivalent boundary, including native multigroup merging and hidden-column projection.

The shared liaison entry retains authorization, group acquisition, revision gates, time-range preparation, metrics, tracing and status handling. Batch results have an explicit schema and idempotent Close. Batches are borrowed until the next pull or Close. Retained QL views snapshot descriptors and values, including repeated columns. The raw-frame emitter independently retains its first borrowed batch before asking for the next one.

No protobuf source, generated API contract, persisted format or frame encoding format changes. Native fanout still receives complete frames eagerly; the new result handle does not make that path streaming.

T02 supplies execution infrastructure; the new raw measure grammar is delivered by T03. Its source shorthand, aliases, timestamp projection, WHERE time, now() and fixed INTERVAL syntax, pagination behavior and current execution limits are documented in the BydbQL user reference. T05 adds transparent compiled-plan reuse without adding query syntax.

Resource contract and limits

One configured execution tracker is shared by liaison ingress, merge operators, final protobuf materialization and response encoding. A Go-only context holder lets the processor initialize the tracker with its configured limit while the caller accounts final encoding against the same tracker. Response reservations remain held through the existing transport scope. Data-node frame coalescing, conversion, encoding and transport copies are reserved before allocation, and the encoded output stays charged after iterator Close until the node finishes sending. Direct frame-emitter callers retain their reservation until iterator Close. Execution sources retain their reservations through owner pins; Close releases execution resources.

Storage decode reservations connect to the same local query tracker. Selected index allocations use a context scope that survives source closure while any output owner remains. Reservations precede selected buffer allocation or reuse; oversized pooled capacities are discarded before attaching them to the query. Existing node-wide storage protection remains active.

The existing parent admission lease is monotonic. Returning execution buffers does not refund spent parent charges. Transport completion releases the parent reservation. The benchmark reports tracker-originated parent charges explicitly; it does not present them as a complete count of admission overhead.

Native receive guards reserve all pending streams before opening them. Measure fanout uses a cached connection with static 64 KiB receive windows, retaining the publisher’s TLS, credential reload and node lifecycle. This bounds transport buffering without reserving the ordinary connection’s possible 16 MiB adaptive window. Other queue traffic retains its existing connection policy.

The guard divides a conservative message allowance among pending streams. With at most 32 MiB remaining, messages are capped at 32 KiB with 256 KiB workspace per stream; larger allowances use 2 MiB workspace to cover gRPC’s larger buffer-pool tiers and partition the remaining allowance. A skewed response can exceed its individual cap even when sequential receipt would fit. This is not an adaptive streaming memory policy. Small-query success under the existing 8 MiB fallback admission allowance is part of native compatibility verification. The explicit 16/256 MiB table requires small-query success and oversized-query rejection or the independently verified complete result.

The benchmark embeds liaison and data nodes in one process. Its process peak reservation counter sums independent node trackers, including conservative allowances; it is neither a single-node peak nor a measurement of actual heap residency. The configured 16/256 MiB limit applies independently at each executing node. A Go context and its accounting objects do not cross the cluster wire.

Investigation of the remaining aggregate comparisons

This investigation explains the inconclusive results; it does not replace or change the acceptance samples. Production still matches the frozen fourth candidate. The deterministic replay command is:

It exits 1 (RED), reproducing native aggregate p50’s interval [1.027927, 1.100497] and QL aggregate p95’s interval [0.889471, 1.189913]. Live feedback remains the unchanged Docker RPC harness; the subsequent controlled probes use its actual query functions through a test-only Go overlay.

Four initial hypotheses were tested: five-pair sample sensitivity, GC tail behavior, recurring accounting/ownership cost, and profiling perturbation. Inspection also revealed a latency-reporting precision limit.

Native aggregate p50: sample sensitivity and precision

Pair 4 sets the upper bootstrap endpoint: candidate 1.993 ms / baseline 1.811 ms = 1.100496963. Diagnostic removal of that pair brings the upper endpoint to 1.064429; removing any other single pair leaves it at 1.100497. Exclusions are used only to identify sensitivity, never to pass the gate. With five observations, resampling one pair three or more times has probability 5.792%; a percentile bootstrap tail can therefore be determined by one pair.

The benchmark’s percentile helper truncates durations to whole microseconds before reporting milliseconds, and the bootstrap consumes those reported values. The borderline pair is only 0.9 microseconds above 1.10 times its reported baseline. Its possible ratio before truncation is [1.099890, 1.101049], crossing the limit. For example, unrounded medians 1.993000/1.811900 give 1.099950, while their reported values give 1.100497. The original raw durations were not retained, so their true endpoint cannot be recovered. This is evidence of insufficient precision at the boundary, not evidence that the original test passed.

The observed 6.2% median increase remains meaningful; the 0.0497 percentage-point endpoint excess cannot be interpreted confidently from microsecond-truncated inputs and five pairs. quantization.json and qlb-t02-gate-diagnosis.json preserve the calculation. Future acceptance runs should retain nanosecond samples and round only for display, using more independent repetitions for a stable tail.

QL aggregate p95: GC-related tail behavior

Opus review fixes and rejected v11 checkpoint

The review is preserved in .omx/reviews/t02-claude-opus-20261015T151749Z/t02-opus-review.md. Necessary fixes retain the existing per-query limits, finite shared pool, monotonic parent charges, execution operators and protobuf wire format.

  • MEASURE admission initially commits its fixed overhead and grows the shared pool commitment atomically with successful charges. The old whole-assignment policy remains for other catalogs. A regression at the common liaison caller holds 32 transport scopes open: the old code refuses query nine; the new code admits all 32 and releases the commitments when the transports close. Growth still refuses pool pressure or the hard per-query ceiling without spending a failed charge. Protector usage is sampled at admission; growth checks its current availability snapshot without sampling the runtime on every allocation.
  • Guarded native fanout no longer uses a fixed 32 KiB message cutoff or the former 32 MiB workspace-policy discontinuity. An actual public query returning a 64 KiB string reproduces the old 65690 vs. 32768 receive refusal. The guard reserves fixed stream/parser costs first, then partitions a fixed fraction of the remaining allowance for bounded message copies. Reserving fixed costs first also permits eight default-budget streams whose windows fit, instead of accidentally rejecting them through the fractional policy.
  • A measure-only receive codec delegates request encoding to the registered protobuf codec and uses the same protobuf decoder for responses. Fragmented receive payloads use the repository’s native-query-codec-flatten buffer pool, bounded by the prepaid message cap and released inside decoding. Single-buffer messages need no flatten copy. This avoids a speculative 1 MiB default gRPC flatten tier for every small stream. Unknown fields, malformed payloads, wire compatibility, oversize refusal and pool loan balance have focused coverage.
  • The connection window is 16 MiB; each stream retains its 64 KiB static window. The connection credit does not add independent payload residency: guarded streams prepay their own window, message-read flow-control delta and codec workspace. A bounded delayed-gRPC experiment exercises eight concurrent 64 KiB responses at a configured 1 ms RTT; this diagnostic is separate from the full real-query acceptance matrices.
  • Operation and global memory-observation counters compile only with querymetrics. Production no-op implementations leave actual tracker/lease enforcement and native pool tracking active. Integration CI and the benchmark orchestrator enable the tag; required T02 cases explicitly reject missing instrumentation. Both build modes have unit/race and lint coverage.
  • Distributed QL tracing completes after final serialization and pipeline Close. The final iterator records rounds and size; an early QueryTrace() cannot snapshot an unfinished result. Regressions exercise the real distributed processor through the QL consumer, pagination, cancellation, serialization failure and repeated Close. Protected real RPCs require a completed final iterator whose end precedes the distributed parent end.
  • Generic integer pool trimming affected actual ingestion encoders. Alternating 8,192/64-row public integer and byte encoders added about 66 KiB and two allocations per pair. Bounded borrowing is confined to decoder paths; the original encoder reuse behavior returns to zero bytes and zero allocations in three repeated microbenchmarks. Measure column scratch uses the same separation between encoder reuse and bounded decoder borrowing.

V11 was rejected before acceptance. Its first tier-aware guard prepaid half the remaining allowance for each fanout. The two-group write_mixed compatibility case exhausted the default monotonic lease: a final 16,118-byte charge could not fit after 8,377,422 bytes had been spent against 8,388,608 bytes. Standalone passed 147 cases; distributed stopped after 58 successes and that failure. All six protected/small-budget RPC cases passed. The candidate-only large diagnostic was stopped, and no acceptance container was run. The frozen source, partial profiles, logs and outcome remain in .omx/bench-reports/qlb-t02-resolution-v11/. The bounded codec and revised fanout partition fix the actual cause rather than raising a memory limit or refunding parent charges.

Production source hashes and shared harness hashes still match both protocol snapshots. These are 40 acceptance-small runs plus ten diagnostic runs, not a completed small/large acceptance matrix.

The separate bounded network diagnostic on final source completed five alternating pairs, ten measured batches per variant, with eight parallel 64 KiB responses and a configured 1 ms RTT. Median batch time was 28.601391 ms with the 64 KiB connection window and 7.118763 ms with the 16 MiB connection window. Both used 64 KiB stream windows; reservations stayed below the asserted 3 MiB bound per 8 MiB query allowance and returned to zero. This demonstrates the transport credit issue under that workload, not a 75% improvement in complete query latency.

At that checkpoint, T02 remained unaccepted pending a reliable latency verdict. All necessary code fixes were retained as uncommitted work; protobuf definitions, persisted formats and the accepted monotonic-charge policy are unchanged.
