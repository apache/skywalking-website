T14 HAVING and compatible collection membership

This is a historical ticket-stage verification record. Current isolated PR 3 checks are recorded separately in the PR 3 verification record.

Implementation base: 8c69d7d1 (T12), on PR #1412. Verification uses Go 1.26.9. Changes are limited to QL grammar/planning, liaison batch execution, generated QL-only integration cases and this ticket’s benchmark. Protobuf, native/data-node operators, indexed storage, frame/persisted formats and memory-protector policy remain unchanged. Temporary-file spilling remains deferred.

The post-review frozen protocol is .omx/t14-review-fixes-frozen-protocol.json. Source hashes for 618 production, test, generated-fixture and benchmark-harness files are .omx/t14-review-fixes-source-manifest.sha256. The original 609-file freeze and .omx/t14-frozen-protocol.json retain earlier measurements; the same 19 kernel and 32 RPC variants are rerun after the review fixes. Documentation is outside the timing manifest. All timing containers use Go 1.26.9, a four-CPU quota, an 8-GiB memory cap and no additional swap. Kernel and RPC timings run sequentially, after integration, package/race checks and resource probes finish. Unrelated host services remain running; these measurements describe that bounded setup.

Execution contract

HAVING evaluates typed expressions over original grouping names and named aggregate calls. Only TRUE retains a completed group; FALSE and UNKNOWN remove it. SELECT aliases do not enter HAVING scope. Nested calls, computed aggregate arguments and nongrouped source references fail before native dispatch. Hidden calls/keys survive until filtering, then visible projection removes them. Repeated calls share state and native branches. Group-only HAVING uses local grouping; scalar empty aggregation produces its SQL empty row before HAVING can remove it.

The existing native raw scan and eligible native aggregate operators are shared with protobuf queries. A local aggregate or complete native keyed merge feeds the same QL filter kernel, followed by visible projection and final OFFSET/LIMIT. HAVING never limits aggregate input or individual native branches. Raw WHERE and HAVING expose separate statistics. Cached plans retain immutable expression and slot metadata; every bind supplies fresh values and execution state.

CONTAINS/NOT CONTAINS preserve legacy infix HAVING/NOT HAVING membership. Integer and string requests require all terms. A scalar source can satisfy one term or duplicates of that term, but cannot satisfy distinct requested terms. NULL sources, scalar NULL requests and empty literal lists do not match; negation complements this result. Empty array parameters retain the existing binding error. Typed membership composes with field/time residuals and post-aggregate HAVING. Ordinary legacy queries retain native routing; MATCH composition stays rejected. CONTAINS is a contextual, measure-only operator, preserving existing contains tags and contains-svc resource/group names across legacy query kinds. See the language guide.

Filtering borrows input value columns and changes selection. Partial matches retain uint16 row indices; all/no-match cases avoid a retained selection. Scratch, expression metadata and selection reservations charge before allocation and balance on EOF, errors, cancellation and repeated Close. Copy counters are structural zero invariants. Unit and kernel pre-timing column-identity checks prove borrowing; the RPC counters alone do not measure copies. Charged decoding scratch is outside that invariant. No new pool is introduced.

Review fixes

Claude Code’s independent Spec/Standards reviews are retained in .omx/t14-claude-review.md. Two main findings were reproduced before the fixes: the global CONTAINS keyword rejected legacy names, and newly accepted typed membership silently filtered a truncated indexed integer array. The parser now recognizes the operator contextually and restricts the new alias to measures.

Before dispatch, QL-evaluated array membership checks current index bindings and their rules through the existing metadata registries. A matching indexed array returns InvalidArgument; metadata lookup failure also fails closed. This check runs after authorization on every execution, including compiled-plan cache hits. It does not filter binding validity windows because native caches apply expired bindings too. Queries without typed array membership skip these metadata reads. The immutable compiled plan remains reusable; index state is not cached in it. This adds metadata work to array-membership RPC timings, reported inclusively.

The one-row indexed INT_ARRAY regression first fails with silently wrong results, then passes with pre-dispatch rejection (.omx/t14-fix-indexed-{red,green}.log). A separate real-RPC regression warms both membership spellings on an unindexed array, adds an expired binding, then checks two cache hits with no recompilation and no data-node dispatch. It is RED without the guard and GREEN with it: .omx/t14-fix-cached-index-{red,green}.log. This correctness probe adds no timing variant or old-ticket benchmark matrix.

The remaining changes share WHERE/HAVING nesting scans and expression-recipe recursion, centralize membership setup and aggregate helpers, validate DISTINCT consistently, and clarify hidden-output naming. HAVING now requires an explicit visible-output slice; nil rejects and closes the source, while an explicit empty slice remains valid. Constructor-selected metric callbacks replace stage booleans, and statistics share one source traversal. Benchmark suffixes and unavailable metric names also have a single definition. Public RED/GREEN evidence is under .omx/t14-review-planner-*, .omx/t14-review-runtime-* and .omx/t14-review-bench-*. The review’s panic-wording concern was rejected because the original log explicitly records PANIC from unmarshalVarArray.

Actual serialized response bytes now come from proto.Size of the six retained, independently checked full BydbQL responses after timing and profiling stop. Reports require total/min/max sizes, all at least the empty envelope size, with overflow-safe consistency checks. Ten report mutations verify rejection of missing or fabricated byte evidence. The original ticket’s output-byte requirement is restored; the native source reference below is corrected.

Focused kernel benchmark

Fifteen variants combine 1/1,024/65,536 groups with no HAVING or thresholds 0/1/50/100. Four more vary membership array length 0/1/16/256 over 1,024 rows. Half the nonempty arrays match their first element; the other half require a full nonmatching scan. Input element count describes array width, not actual comparison count.

All 19 variants × five one-second samples pass independent physical-row and selection checks, borrowed-column checks and balanced reservations. Runtime is 114.282 seconds. Raw results are .omx/t14-review-kernel.log; all samples and medians are .omx/t14-review-kernel-median.json.

Focused RPC benchmark protocol

P(T14), qlb_t14, has 12 grouped variants at each input size: native/local routes, each with a baseline, thresholds 0/1/50/100 and hidden-AVG 50%. Both routes compute the same 16 group means from host=row%16, nullable f=(row%29-14)/4, with NULL every seventh row and duplicate writes. The baseline selects AVG twice. Predicate variants repeat AVG in SELECT and HAVING; hidden variants select only host. All use complete input and share the same two aggregation state lanes. Native execution has exactly two SUM/COUNT branches; local execution has one raw scan. An existing test hook forces local execution for the reference route.

Quantile thresholds come from independently computed means. A nominal 1% of 16 groups rounds up; ties can retain more. Thresholds 0/100 reject/retain all groups. The hidden variant omits two output fields relative to its route’s baseline; its latency difference includes narrower output, rather than isolating HAVING.

At 1,024 rows, eight additional variants compare both membership spellings at array lengths 0/1/16/256. Their separate fixed 1,024-row fixture supplies 256 candidates per width. A native entity predicate selects width; typed membership and f::FIELD >= 0 precede COUNT aggregation and HAVING COUNT(f::FIELD) > 0. Empty arrays yield no groups. Other widths pass 128 rows and produce eight groups with count 16 each. Membership does not scale with the main 32,768-row fixture.

This is 32 variants per repetition, five fresh containers, one worker, 256-MiB query budgets, 100 timed/5 warmup calls at 1,024 rows and 20 timed/3 warmup calls at 32,768. Each cardinality starts a fresh cluster process. All warmups and six retained timed responses receive full independent checks outside timing; every timed call checks result count. Each timed call must hit the compiled-plan cache without compilation. Reports retain all latencies and CPU/heap profiles.

Required work: raw WHERE sees only membership candidates; HAVING sees completed groups; hidden outputs never serialize; repeated calls add no branches/lanes; there are no intermediate DataPoints or leaked reservations/results/owners/pool references. Native source counters are 4N and frame counters 4G across two branches and two replicated physical leaves; local counters are 2N with N rows reaching local aggregation. These are decoded/transport work, not physical storage reads. Native merge state is 18G bytes; local state is 16G (membership 8G), excluding keys/capacity/other reservations.

CPU and allocation snapshots cover the client, liaison and both nodes in one process. Shared filter-kernel profiles do not isolate HAVING CPU. Process peak reservations are a global high-water mark and can include earlier variants; per-operator peak retained bytes, native retained frame bytes, total cumulative parent lease charges and physical storage reads are explicitly unavailable. Available stage reservation totals balance releases; the monotonic tracker-lease counter is cumulative and is not represented as refunded admission.

The owning command is documented in the benchmark guide. No earlier-ticket timing matrix is expanded. G1’s historical T02 inconclusive comparison remains unchanged; these are measurements of the new capability and its current aggregation reference, not a cross-revision compatibility verdict.

Resource probes and native limits

These probes predate the review fixes and are retained as evidence of the existing native limits. Post-review generated RPC cases, the cached-index regression and the same focused benchmarks verify budgets/cleanup for the changed paths. No large-input throughput claim is added.

Separate fresh four-CPU/eight-GiB processes probe 100,000/1,000,000 rows at 256 MiB and 100,000 at 16 MiB. Before owning queries, bounded QL windows independently verify every fixture row. Five attempts per native/local route then check either the complete independently expected result or ResourceExhausted without partial output, followed by cleanup and small-query recovery.

At 100,000/256 MiB the representative local failure requests 12,517,408 bytes after 262,138,987 bytes are already charged against 268,435,456. At 1,000,000/256 MiB, native input decoding requests 21,880,784 after roughly 264,745,051 bytes; failure occurs in the first SUM branch before merge/HAVING. The 16-MiB readiness query requests roughly 15.1 MiB after roughly 14.1 MiB is already charged. The same prerequisite blocks a meaningful 1,000,000/16-MiB owning probe, so it is not repeated or reported as a passed capability test.

All attempted paths release live resources; successful-readiness runs also pass small-query recovery. The blocked readiness run verifies cleanup but does not claim owning-query/recovery evidence. Process-global reservation high-water ranges are 501,510,652–582,353,446 bytes for 100,000/256 MiB and 591,295,319–591,745,252 for 1,000,000/256 MiB. These combine one liaison and two independent data-node trackers and can include earlier readiness, so comparing them with a single 256-MiB tracker would be incorrect. They are not per-route peaks. Probe elapsed/allocation observations overlap other verification jobs and are not used as isolated performance measurements.

Reports are .omx/t14-resource-reports/qlb_t14_resources_<rows>rows_<budget>mib.json; logs are .omx/t14-resources-{100k-256,1m-256,100k-16}.log. Large failed inputs provide resource-bound evidence, not HAVING throughput. Spilling local aggregate state alone would not bypass earlier native input decoding/materialization limits.

Existing indexed-array projection limitation

Historical T14 evidence follows. The native indexed-array projection repair is already included in merged PR #1417. PR 3 inherits that repair while preserving T14’s typed indexed-array membership rejection. The reproducer and diagnosis below describe the ticket-stage behavior before that native repair.

The initial real standalone smoke fails on the old membership spelling:

SELECT rid FROM MEASURE ql_t14_legacy IN replicated_group
TIME BETWEEN ? AND ? WHERE labels HAVING ? ORDER BY TIME ASC

Binding the string red returns STATUS_INTERNAL_ERROR with unmarshalVarArray failed: invalid variable array: invalid query message. Evidence remains in .omx/t14-standalone-smoke-v1.log and its JSON report. This is a QL RPC reproducer, not a native Query oracle. No baseline-revision RPC rerun is claimed.

Read-only source analysis locates the existing boundary: standalone writing stores indexed array elements as separate index fields and skips the packed TSDB column (banyand/measure/write_standalone.go). Index projection retains only the last stored term (banyand/internal/storage/index.go, appendSearchHit), which measure query decoding treats as a packed array (banyand/measure/query.go). STRING_ARRAY then lacks the expected packed delimiter and can panic; INT_ARRAY can silently become a one-element array. Hidden criterion projection reaches this path even when SELECT omits the array. The liaison has not yet received a batch and cannot repair it with a QL filter or a ::TAG qualifier.

The review adds a real-RPC INT_ARRAY reproducer: an acknowledged [1,2] write projects as [2]; typed CONTAINS 1 and legacy membership plus a field residual silently return no row, whereas CONTAINS 2 returns it. Evidence is .omx/t14-claude-review-indexed-probe.log. This new accepted-query exposure is fixed by the pre-dispatch guard, rather than left as a documentation-only limit.

T14 leaves native storage/decoder paths unchanged. All typed string/integer array cases and both spellings remain on unindexed arrays, alongside generated indexed-array rejection cases with no data dispatch. Ordinary native-route compatibility uses indexed scalar string/integer sources to pin all-terms, duplicates, binding and null behavior. This does not establish that native indexed array projection works.
